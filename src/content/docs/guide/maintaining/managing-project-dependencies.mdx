<p class="lead">**Every dependency is code you ship without having written it.** Choose them carefully, lock their versions, update them in small steps, and audit them regularly. That keeps the project stable and secure as it grows.</p>

## Understanding Project Dependencies

[Dependencies](/guide/glossary/#dependency) make development faster and more efficient, but they bring risks too: bugs, security vulnerabilities, even conflicts with other dependencies.

Managing dependencies means knowing which ones your project needs and making sure they work with each other and with your project's requirements.

There are two types of dependencies to consider:

1. **Direct dependencies**: The packages you explicitly add to your project (like including a package for image processing).
2. **Transitive dependencies**: The dependencies of your dependencies, brought in automatically with the packages you added directly. They can grow complex quickly, especially in large projects.

## Choosing Dependencies Wisely

A big part of managing dependencies is choosing them well from the start. Look at four things:

1. **Reputation and Popularity**: Choose dependencies that are well-maintained with regular updates, widely used, and backed by good documentation and an active community. That way, issues get addressed promptly and the dependency stays reliable.
2. **License Compatibility**: Each dependency has its own license, and it can affect how you use and distribute your project. Make sure the licenses of all your direct dependencies are compatible with your project's license, to avoid legal complications.
3. **Performance**: Check how each dependency affects performance. Some libraries significantly increase load times or memory consumption, and users notice. Opt for lightweight dependencies when possible to avoid performance bottlenecks.
4. **Security**: Always review dependencies for known vulnerabilities. Use tools or services that identify security issues in dependencies, so you don't expose your project to unnecessary risks.

## Dependency Management Tools

Dependency management tools make it easier to track, install, and update the dependencies your project requires. Each ecosystem has its own:

- **JavaScript**: [npm](https://www.npmjs.com/), [Yarn](https://yarnpkg.com/), [pnpm](https://pnpm.io), are popular package managers for JavaScript projects, but there are many others available.
- **Python**: [pip](https://pypi.org/project/pip/) is the default package manager for Python, while [pipenv](https://pipenv.pypa.io) and [Poetry](https://python-poetry.org/) offer more advanced dependency management features.
- **Java**: [Maven](https://maven.apache.org/) and [Gradle](https://gradle.org/) are commonly used build tools that handle dependency management for Java projects.
- **Ruby**: [Bundler](https://bundler.io/) is the go-to tool for managing dependencies in Ruby projects.

Most of them have features for locking versions, auditing security, and simplifying updates. Those features ease dependency maintenance significantly over time.

## Dependencies Versioning

**Dependencies are versioned** so that developers can specify which version of a dependency their project requires. Versioning helps keep your project stable, so updates don't introduce [breaking changes](/guide/glossary/#breaking-change).

**The most common versioning scheme is [Semantic Versioning (SemVer)](https://semver.org/)**, which uses three numbers (such as 1.2.3) to indicate the significance of changes. Major versions indicate breaking changes, minor versions add new features, and patch versions include bug fixes.

So when you choose dependencies, look at their versioning scheme and how they handle updates. It tells you when to update and how to manage breaking changes.

Decide on a versioning strategy for your project early on, and communicate it clearly to contributors and users. Then everyone knows how versions are managed and what to expect from updates. For instance, you might update minor and patch versions regularly, but test major versions more thoroughly before adopting them.

Automation tools can notify you when new versions are available, so you stay on top of updates without manually checking each dependency.

## Pinning or Locking Dependencies

Pinning or locking dependencies means specifying exact versions of your project's dependencies, so every environment behaves the same. It prevents unexpected updates that could introduce breaking changes or security vulnerabilities.

Most dependency management tools can pin dependencies. For example, npm writes a `package-lock.json`, Yarn a `yarn.lock` and pnpm a `pnpm-lock.yaml`: commit it. In Python, `Pipfile.lock` or `poetry.lock` serves a similar purpose.

Pinning is especially useful for projects deployed to multiple environments, such as development, staging, and production. With locked dependencies, each environment uses the same versions, which reduces the risk of compatibility issues.

## Updating Dependencies Safely

Updating dependencies is a delicate balance: you want new features and security patches, without breaking changes. Here's how to update safely:

1. **Use Automation for Updates**: Tools like [Dependabot (GitHub)](https://docs.github.com/code-security/getting-started/dependabot-quickstart-guide) and [Renovate](https://docs.renovatebot.com/) automate dependency updates and can even create pull requests for each new version. These tools typically include tests to check compatibility, so updates are more manageable.
2. **Test Before Upgrading**: Even minor updates can introduce unexpected changes. Before deploying updated dependencies, make sure your test suite covers the main features. If you don't have tests, write some for critical areas before updating.
3. **Read Release Notes**: Read the release notes of each dependency update to see what changed. Look for breaking changes, new features, and security fixes, and assess the impact on your project.
4. **Batch Updates Carefully**: When updating multiple dependencies, it's safer to go step by step. Updating everything at once risks several issues at the same time and makes debugging harder.
5. **Monitor for Security Alerts**: Use tools like [GitHub Advisory Database](https://github.com/advisories), or [Dependabot](/guide/glossary/#dependabot) to get notifications about security vulnerabilities in your dependencies. Address these alerts promptly to keep your project secure.

## Handling Dependency Conflicts

Conflicts happen when two or more dependencies rely on incompatible versions of another library. To prevent and resolve them:

1. **Limit Direct Dependencies**: Reduce the number of direct dependencies when possible by relying on core libraries or dependencies with minimal additional requirements. The fewer dependencies you have, the fewer chances of conflict.
2. **Isolation**: Some languages offer ways to isolate environments for dependencies (for example, virtual environments in Python, node modules in JavaScript). Each project or environment then manages its own versions, which reduces the risk of conflicts.
3. **Use Scoped Versions**: Some tools allow multiple versions of a dependency to coexist. For instance, npm can sometimes install different versions for different dependencies to avoid conflicts.

## Security Considerations

Dependencies can introduce security risks. To limit them:

1. **Regularly Audit Dependencies**: Use tools like `npm audit`, `pip-audit`, `pipenv check`, or other command-line tools to scan your dependencies for known vulnerabilities. Make regular audits a habit to catch security risks early.
2. **Stay Informed**: Monitor announcements from major dependencies for updates on vulnerabilities. Subscribe to mailing lists or security notifications if available.
3. **Remove Unused Dependencies**: Regularly review your project for unused dependencies and remove them. Each dependency is a potential security risk or contributes to project bloat, so keep your project lean and clean.
