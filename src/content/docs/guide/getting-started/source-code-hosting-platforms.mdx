<p class="lead">You will end up on GitHub: most projects you'll use or contribute to live there, and every tutorial assumes it. A few communities chose otherwise, for reasons of control, workflow or principle: GNOME runs its own GitLab, Zig moved to Codeberg, and the Linux kernel still takes patches by email. Here's where each one lives, and what changes when you contribute there.</p>

<InShort>

- GitHub is the default, with more than 180 million developers. Learn it first.
- GitLab is the one you can run yourself: GNOME, Debian, KDE and freedesktop.org do. A pull request is a merge request there, numbered `!123`.
- Codeberg is a non-profit running Forgejo. It looks like GitHub, and Zig moved there in November 2025.
- On sourcehut, and for the kernel, `git send-email` replaces the pull request.
- Contribute wherever the project is. For your own, pick GitHub unless you have a reason not to, and push to a second host if you want a backup.

</InShort>

## GitHub is where you'll start

More than 180 million developers have an account on GitHub, and 36 million joined in a single year, according to [Octoverse 2025](https://github.blog/news-insights/octoverse/octoverse-a-new-developer-joins-github-every-second-as-ai-leads-typescript-to-1/). A repository there comes with everything a project needs (1), and a **Sponsor** button (2) when the maintainers accept money:

/>

- **Issues and pull requests**: the contribution flow every other platform copies. [Git and GitHub Basics](/guide/getting-started/git-and-github-basics/) covers it.
- **[Actions](/guide/glossary/#github-actions)**: CI, free on public repositories with GitHub's standard runners.
- **Discussions, Sponsors, Codespaces and Copilot**: questions, money, a cloud editor, AI, in the same account.

Microsoft has owned GitHub since 2018. Some projects left over it, or over the AI features spreading across the site: [Zig's announcement](https://ziglang.org/news/migrating-from-github-to-codeberg/) gives one project's reasons. For a contributor, that changes nothing: the projects are where they are.

## GitLab is the one you can run yourself

GitLab is two things: [gitlab.com](https://gitlab.com/), a hosted service like GitHub, and a product you can install on your own server. Large communities do the second, to own their data and their accounts:

| Community       | Instance                                                                  |
| --------------- | ------------------------------------------------------------------------- |
| GNOME           | [gitlab.gnome.org](https://gitlab.gnome.org/)                             |
| Debian          | [salsa.debian.org](https://salsa.debian.org/)                             |
| KDE             | [invent.kde.org](https://invent.kde.org/)                                 |
| freedesktop.org | [gitlab.freedesktop.org](https://gitlab.freedesktop.org/) (Mesa, Wayland) |

Others, like [Inkscape](https://gitlab.com/inkscape/inkscape) and [F-Droid](https://gitlab.com/fdroid/fdroidclient), live on gitlab.com. The flow is the same as on GitHub, under other names: a pull request is a **merge request** (1), numbered with `!` instead of `#` (2).

| GitHub       | GitLab                               |
| ------------ | ------------------------------------ |
| Pull request | Merge request, `!123`                |
| Organization | Group                                |
| Actions      | CI/CD pipelines, in `.gitlab-ci.yml` |

**Each instance is its own site.** Your gitlab.com account doesn't work on gitlab.gnome.org: you create one there too. gitlab.com's free tier gives 400 CI minutes a month and 5 users per group; its [open source program](https://about.gitlab.com/solutions/open-source/join/) lifts that to the top tier and 50,000 minutes (as of September 2026).

## Codeberg is a non-profit, with Forgejo underneath

[Codeberg](https://codeberg.org/) is run by Codeberg e.V., a non-profit association in Berlin, and hosts free and open-source projects only. It runs [Forgejo](https://forgejo.org/), a forge that started as a soft fork of Gitea in late 2022 and [became a hard fork](https://forgejo.org/2024-02-forking-forward/) in February 2024. If you know GitHub, you know [Forgejo](/guide/glossary/#forgejo): code, issues, pull requests (boxed), actions.

<ContentImage

Zig moved there on November 26, 2025, after ten years on GitHub. Forgejo itself is developed on [Codeberg](/guide/glossary/#codeberg). CI runs on Codeberg's Woodpecker instance, which you ask access to, or on Forgejo Actions with runners you provide ([Codeberg's docs](https://docs.codeberg.org/ci/)). Forgejo is also a single binary you can host yourself.

## On sourcehut and the kernel, you send patches by email

Some projects have no pull request button. You turn your commits into emails with `git send-email`, send them to the project's mailing list, and reviewers answer inline, in their mail client. The Linux kernel and Git itself work that way, on their own mailing lists.

[sourcehut](https://sourcehut.org/) is a forge built around it. aerc, a terminal mail client hosted there, asks contributors to configure their clone once, then send:

```bash
git config format.subjectPrefix "PATCH aerc"
git config sendemail.to "~rjarry/aerc-devel@lists.sr.ht"
git send-email --annotate -1
```

- [git-send-email.io](https://git-send-email.io/) walks you through the setup for your mail provider.
- On sourcehut, contributing is free. Hosting your own projects takes a subscription, from $4 a month, with CI included (as of September 2026).

## The older ones, in one line each

- **[SourceForge](https://sourceforge.net/)** was the big host of the 2000s, and still hosts downloads. In 2015, it wrapped GIMP's Windows installer in its own, which installed other software: [GIMP's statement](https://www.gimp.org/news/2015/05/27/gimp-projects-official-statement-on-sourceforges-actions/) says what happened.
- **[Launchpad](https://launchpad.net/)** is Canonical's platform for Ubuntu: bug reports, translations and package archives.
- **[Bitbucket](https://bitbucket.org/)** is Atlassian's, mostly for private company code. Its Mercurial repositories went read-only on July 1, 2020, and were [disabled](https://www.atlassian.com/blog/bitbucket/sunsetting-mercurial-support-in-bitbucket) in August 2020.

## Which one for you

**To contribute, go where the project is.** Create an account on its instance, or set up `git send-email` once, and read its `CONTRIBUTING.md`: the rest of this guide applies everywhere, under other names.

**For your own project, pick GitHub unless you have a reason not to.** It's where your users and contributors already have an account. If you have a reason, Codeberg and GitLab are good homes, and nothing stops you from pushing to two hosts at once:

```bash
git remote set-url --add --push origin git@github.com:you/project.git
git remote set-url --add --push origin git@codeberg.org:you/project.git
git push
```

Once a remote has a push URL, Git stops pushing to its fetch URL: add both. Every `git push` then updates the two copies, and one of them is your backup.

## Do this now

<Checklist id="source-code-hosting-platforms">

- [ ] Check where the three projects you use most really live: the GitHub repository can be a mirror, and its README says so.
- [ ] If one of them lives on its own GitLab or on Codeberg, create an account there before you need it.
- [ ] If you maintain a project, add a second push URL to its remote, so every push leaves a copy somewhere else.

</Checklist>
